# Visual review — implementation v1

Status: **not accepted**. The user reviewed the running version and found it visually generic, overfull, and lacking an evident animation demonstration. Publication and further page expansion are paused. The original implementation objective remains active; the next design pass requires a focused visual review before broad changes.

- Current first viewport: `../qa/home-desktop.png`.
- Full desktop/mobile pages: `../qa/screenshots/`.
- Actual hover: `../qa/animations/research-hover.gif`.
- Actual route transition: `../qa/animations/research-to-detail.gif`.
- Reference observations: `references.md`, especially the accessible DeepMind index, Google article header, Meta research feature, and shadcn Command interaction.

## Findings

1. **The hierarchy reads as a template.** A large name, uppercase eyebrow, affiliation, role, research interests, advisor, link row, university lockup, and latest note all arrive before the work. Several repeat the same identity or TIDE information. The first viewport is optimized for fitting information, with limited editorial selection.
2. **The work imagery is factual but poorly art-directed.** The two TIDE crops read as unrelated generated pictures, with no clear visual explanation of the paper. The SASBO figure contains ten thumbnails and tiny scientific labels inside a cover slot. Correct sourcing alone does not make an effective cover. The original complete figure belongs in the detail page; the gallery needs a deliberate selection of readable visual material.
3. **The modules lack a dominant visual moment.** Repeated heading/link rows, similar title weights, neutral metadata, and familiar rounded media containers flatten the reading rhythm. The larger name dominates the representative research. The reference DeepMind composition gives a primary story a stronger image/title relationship.
4. **The interaction treatment is generic and hard to discover.** Current hover uses image scale, a dark veil, text translation and small action buttons. The motion exists, but contributes little to understanding the research. The shared transition is reached through a secondary Details action. The cover itself does not communicate a clear primary action. No visible demonstration was presented before review.
5. **The project screenshot is too reduced.** An entire application viewport is squeezed into another padded media container. Its useful controls and book workflow are too small to read, producing nested whitespace without a strong composition.
6. **Functional verification and visual acceptance are separate.** The build and most behavior checks have passed. That evidence does not establish aesthetic quality. The current version has not passed the user's visual acceptance.

## Next review scope

Review only one homepage first viewport and one TIDE card/feature before changing the remaining pages. Keep the implemented information architecture and underlying routes available. Present default, hover, reverse, keyboard/touch and detail-entry states together in a real browser sample. Confirm the visual hierarchy and image treatment at that scale, then apply the accepted system to the other pages.

The proposed direction gives research imagery and its title the primary role, reduces the personal introduction to a compact identity block, removes duplicate news/affiliation explanations from the first viewport, and crops source material around a readable subject. TIDE's motion should demonstrate a concrete relationship in the existing paper imagery rather than add another decorative reveal. Exact imagery and choreography remain open for review; no new scientific content or results should be invented.
